Multica has no sign-in: one server serves one local user and treats every request as that user. The web app, Desktop, the CLI and the daemon need no credential. This page describes the one credential left: the temporary token an agent uses while it runs a task.

## Temporary tokens for agent runs

When the daemon claims a run, the server creates a temporary token for that run, prefixed with `mat_`. It is bound to the current user, workspace, agent, and run, is valid for at most 24 hours, and is cleaned up when the run ends.

The daemon injects this temporary token into the AI coding tool. Requests made by the agent are therefore recorded as agent actions, and the token can't be used to reach sensitive operations restricted to users or owners.

These tokens are created automatically by the server; users never need to save or manage them.
